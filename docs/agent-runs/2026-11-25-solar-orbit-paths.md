## Changes and decisions

- Sampled the same offline Sun-centered J2000 ecliptic ephemeris as the worlds and put all nine guides through the same radial display mapping. Reused the resulting geometry, not a date-accurate trajectory or a trail; see [ADR 0011](../adr/0011-sample-fixed-solar-orbit-guides.md). There is no Sun path.
- The View panel's **Orbit paths** toggle is on by default and lasts for the visit; hiding paths removes them from rendering and hit testing. A visible globe has priority; overlaps resolve by depth then body order. Hover highlights the guide and its world. Clicks and taps use the same follow action as body meshes and the picker. Gesture guards and the legacy Earth–Moon modes stay separate.
- Changed `README.md`, `index.html`, `styles.css`, `src/app.js`, `src/astronomy.js`, `src/solar-display.js`, `src/solar-view.js`, `tests/browser.test.js`, `tests/model.test.js`, `tests/fixtures/solar-horizons.js`, the ADR and this journal. No new dependencies, permissions, or runtime services.

## Performance review revision (2026-11-28)

The original `review.patch` is preserved. Review found that the app did all 2,304 ephemeris evaluations before the first Solar frame and made an exact guide pick for each raw pointer event. The near-term fix changes neither the guide shapes nor selection priority:

- The build now packs the same mapped coordinates as deterministic little-endian Float32 in the existing bundle. No extra runtime asset request and no client ephemeris guide sampling. The first Solar render submits worlds without guides; the next builds and draws them if enabled. The standalone packed array is 37,036 bytes raw / 27,461 bytes gzipped; the production JS bundle grew by about 38 kB raw and 28 kB gzipped. The tests compare decoded coordinates for all nine guides and assert the payload bound.
- The frame consumes only the latest valid pointer position. It performs at most one hover pick, also covering revalidation of an active highlight when the model changes. Leaving, dragging/pinching, camera changes, hiding, and losing WebGL invalidate the queued position. Click/tap still use the exact release position and last painted scene. Unchanged hover does not repaint the scene.
- Instrumented Chrome 158/SwiftShader with a 120-event burst inside one RAF. Baseline did 120 synchronous checks, plus one active-hover revalidation in the throttled warm sample (unthrottled cold/warm handler time 24.8/13.6 ms, 4× throttled 97.2/56.0 ms). The revised build did latching only in the handlers and one check on the following RAF (handlers 1.0/0.6 ms, 3.7/1.7 ms at 4×; actual cold check 2.5 ms unthrottled and 10.7 ms at 4×, warm 0.6/1.9 ms). The baseline's cold ephemeris batch took 67.1 ms unthrottled and 245.7 ms at 4×; revised sampled nothing at runtime and prepared geometry in 4.4/18.1 ms. The trace records the first two Solar submissions as 0 and 9 guide draws. These are CPU-side submissions, not compositor presentation timestamps; first-use WebGL work still produces long tasks with SwiftShader. No hardware-GPU or real-device timing is claimed.
- The revised first render with guides spent 508 ms inside `renderer.render` in the first SwiftShader context and 76 ms in the subsequent 4× context, after the 4.4/18.1 ms preparation intervals above. The replay of the original patch (`perf-baseline-replay.log`) measured 184/163 ms in its combined worlds-and-guides render and reproduced the startup sampling and pointer bottlenecks. These are software-renderer samples with shader/cache effects, not an end-to-end startup improvement or comparable cold hardware-GPU benchmarks. The change eliminates the synchronous ephemeris batch rather than moving it to the later frame, but does not promise a long-task-free WebGL startup.
- See `perf-reproduction.md`, `perf-probe.mjs`, `perf-baseline.log` and `perf-revised-final.log` under `.git/info/solar-orbit-paths/`. Two equivalent clean in-memory builds also produced identical bundle hashes (`asset-reproducibility.log`). The in-suite controlled-frame check verifies that a 120-input burst reads coordinates once, uses the latest input, and is discarded on pointer leave. The scope did not require a projected-path cache after coalescing.
- The first full revision run was stopped at the phone round-trip screenshot: its two captures straddled guide initialization, and formatting the resulting binary deep-equality failure stalled the test process. The isolated run with byte equality confirmed the mismatch (`revised-phone-before.log`). The test now captures after both startup frames, still requires exact byte equality, and retains the different-angle, tap, and pinch assertions.
- Final verification: `npm test` 22/22 (`revised-unit-final.log`); focused render/guide tests 3/3 (`revised-targeted.log`); isolated corrected phone case 1/1 (`revised-phone-after.log`); `npm run test:browser` built and passed 42/42 (`revised-browser-final.log`). `review-revised.patch` is the cumulative change from `af568a0`; `performance-only.patch` is the delta from the original `review.patch`. Both forward- and reverse-check without staging.
